# SagaForge Trial 067: 「ただのファンタジーRPG」から収集スマホRPGの第一段階へ寄せる

ユーザー評価として、前回までの SagaForge / 星紋遠征隊は「全然ロマサガRSとは程遠い」と受け止められた。ここで大事なのは、実在IP・公式素材・商標・ロゴ・キャラ・公式文言・公式確率・公式UIをコピーすることではない。目指すのは、**キャラ収集、スタイル育成、5人編成、クエスト周回、Round/BP/OD風の戦闘テンポ、報酬/召喚の戻り先**という体験パターンを、非侵害のオリジナルUIとして段階的に近づけること。

公開プレイアブルは、最終レポートで確認済みURLとして案内する。記事本文にはローカルパスや内部ホスト名を残さない。

## 前回の何が遠かったか

Trial 066 までで、作戦チケット、5人行動順、BP/OD、勝利後報酬はかなり増えた。しかし初見ではまだ次の弱さが残っていた。

| 不足 | なぜ遠く見えたか |
|---|---|
| ホームの主導線が見えにくい | 機能カードが多く、ログイン直後に「何を押せば周回ループへ入るか」が分かりにくい |
| スタイル/5人編成/クエスト/戦闘が散っている | 収集スマホRPGで期待される「育成対象を決めて、5人を組み、周回へ行く」判断が一枚で読みにくい |
| 戦闘テンポが説明に寄りがち | BP/OD/連携/報酬は存在するが、初回体験で一気に触れる入口が弱い |

## 今回潰した差分

今回は `playables/sagaforge-app/index.html` に **Trial 067** の前面ボードを追加した。記事化より先に、触れるURLの体験を改善している。

追加したもの:

1. **Trial 067ホームボード**
   - ホーム密度、スタイルカード、5人編成と陣形、クエスト→戦闘テンポ、10連結果と戻り先、次の差分を一枚に集約。
2. **5つの即時操作ボタン**
   - 日課から出撃
   - スタイル育成
   - 5人陣形
   - クエスト選択
   - Round解決
3. **5人編成の見える化**
   - 前衛2・中衛2・後衛1、武器、予約技、BP、弱点候補をホームで確認。
4. **クエスト候補の表示**
   - 消費スタミナ、推奨戦力、育成報酬の方向を出撃前に表示。
5. **Round/BP/OD短縮解決**
   - `Round解決` で勝利リザルトを生成し、能力値・技Rank・ピース・記憶片・技書を増やし、育成/召喚へ戻れる状態にした。

## 触って分かる変化

今回のプレイアブルでは、ホーム上部に Trial 067 のボードが出る。そこで「日課から出撃」を押すと、育成対象・5人編成・クエスト・OD予約がまとまり、周回画面へ移動する。「Round解決」を押すと、戦闘画面で勝利報酬が発生し、育成または10連へ戻れる。

つまり、単なるファンタジー紹介画面ではなく、少なくとも第一段階として次のループが見える。

```text
ホーム資源確認
  -> スタイル育成候補
  -> 5人編成/陣形
  -> クエスト選択
  -> Round/BP/OD戦闘
  -> 能力値・技Rank・ピース・報酬
  -> 育成/召喚/再戦へ戻る
```

## まだ遠い点

まだ「かなり近い」とは言えない。次の差分が残っている。

- 戦闘演出がまだカード/ログ中心で、連携・ODの気持ちよさが弱い。
- スタイルごとの役割差はあるが、複数スタイルの切り替え・継承・育成優先度の悩ましさは浅い。
- ガチャ演出と10連結果はあるが、演出段階・昇格・重複ピース変換の手触りがまだ薄い。
- ホーム情報は濃くなったが、スマホRPGらしいイベントバナー、ミッション、プレゼント、デイリー導線の視覚的なメリハリはまだ不足。

## 次に潰す差分

次サイクルでは、今回作った Trial 067 ボードを土台にして、以下を1〜3個に絞って潰す。

1. **戦闘テンポ強化**
   - 5人の行動カットイン、連携段階、ODゲージ消費、複数敵へのダメージポップをもっと明確にする。
2. **スタイル育成の厚み**
   - 同一キャラ別スタイル、継承技、限界突破、技Rank、ピース不足/突破可能の差を画面上で判断しやすくする。
3. **召喚→育成戻りの気持ちよさ**
   - 10連結果をスタイルカードとして見せ、重複時のピース変換と育成候補更新をもっと派手にする。

## 検証メモ

今回の変更では、静的プレイアブルを中心に更新した。`scripts/build_preview.py` の DOGFOOD_ORDER に Trial 067 を追加し、preview 再生成対象に含めた。公開URLと主要アセットの HTTP 200 確認、ブラウザでの主要ボタン表示/操作確認、スクリーンショット保存を実施した。

AIDD-Spec 的には、今回の学びは「見た目のRPGらしさ」ではなく、**ユーザーが期待する日課ループを入口に置くこと**だった。AIに頼む上流指示には、単に「RPG風」ではなく「ホームで資源・スタイル・5人編成・クエスト・戦闘テンポ・報酬戻りを一枚で触れる」と書く必要がある。
